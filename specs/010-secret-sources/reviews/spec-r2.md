FINDINGS:
- [major] FR-010 / US4 AS1 – FR-010 contradicts itself: "MUST NOT attempt more logins than today's lockout protection allows" (= at most one failed login per node per 60 s) vs a changed re-read value lifting the pause (second login within 60 s; if rejected again and the value changed again — rotation in progress, alternating values — nothing stops further failed logins). – What is the new upper bound? Proposed: re-read at most once after a rejection; if changed, exactly one further login without a pause; if that is rejected too, pause 60 s without another re-read → at most two failed logins per node per 60 s. Also: simultaneous rejections (parallel attempts once credentials are confirmed) share one re-read.
- [major] FR-001 / FR-004 / FR-006 – Not defined whether a node that overrides the source inherits group-level parameter names (e.g. group Parameter Store in account A with group names, node overrides with another region/AWS profile → names for account A read in account B). – Proposed for FR-004: group-level names apply only to nodes whose effective source is the group's source; a node with its own source override MUST configure its own names for the required kinds (else startup configuration error). Or state the opposite explicitly.
- [minor] FR-009 / US3 AS2 / US2 AS4 – "AWS access unavailable" (warning, exit 0) vs error (exit 1) not told apart (no credentials in the chain, expired SSO token, store unreachable/timed out, AccessDenied for a valid identity, unknown local AWS profile). – Proposed: unavailable = no credentials resolvable, or store unreachable/timed out (warning, exit 0); access denied on a parameter and an unknown AWS profile are errors (exit 1).
- [minor] FR-010 – "re-read value differs" does not say which values or credentials. – "differs = username or password differs"; say whether a rejected end-to-end login re-reads the e2e credentials or FR-010 covers only username/password.
- [minor] FR-011 / Edge case 30 s – Unclear whether a fetch returning a value that fails validation (empty, `StringList`, forbidden characters) counts as a failed fetch (30 s back-off, WARN under FR-013). – "A fetch whose value fails validation counts as a failed fetch (invalid value)."
- [minor] FR-008 – Today's next step for rejected credentials says fix <VAR> and restart the MCP client; for Parameter Store it must differ. – "The next step refers to the effective source (for Parameter Store: correct the parameter value; no restart needed)."
- [minor] SC-005 – "no measurable extra time" has no testable tolerance. – e.g. at most 50 ms difference from the environment-variable source.
