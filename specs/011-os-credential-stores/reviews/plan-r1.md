PLAN: specs/011-os-credential-stores/plan.md  ROUND: 1

The four findings of `reviews/spec-r2.md` are resolved in spec.md. Fan-out allowance: FR-008 now adds it only while the credentials are not held, for both sources. Top-level `source.prefix`: FR-005 keeps today's meaning, and overrides without their own `prefix` use the profile-wide prefix. Linux locked collection: the Assumptions now say it is unlocked through the session's prompt. FR-017: access denied is checked with test doubles, plus a manual step on macOS and Linux and none on Windows. The plan, research R-1 to R-16, data model, contracts and quickstart cover every FR, US and SC of the spec. The research decisions agree with each other and with the contracts. The coverage gaps are SC-006 and FR-013, which have no test row, and parts of FR-015 and SC-007 in R-16. I checked the plan against the code: `NodeSecrets`, `CredentialGuard`, `AdapterGatewayFactory`, `SecretTiming`, `CredentialResolver`, `SecretPlan`, `ConfigValidator`, `ConfigSummary`, `Wiring`, `Launcher`, `CliRunner`/`SystemProcessLauncher`, `PackageBoundaryTest`, `LiveTarget`/`TestWiring` and the shade configuration in `pom.xml`. I confirmed that jna-platform 5.17.0 has no `CredRead`/`CREDENTIAL` mapping (javap of `Advapi32`, no `WinCred` class). Not relocating JNA, `ERROR_NOT_FOUND` 1168, `ERROR_NO_SUCH_LOGON_SESSION` 1312, UTF-16LE blobs from `cmdkey`/the UI, `security -g` printing to stderr with the `0x` hex form, exit code 44, and `secret-tool` adding no line break on a pipe all match what I know. I could not verify the message texts of `security` and `secret-tool` here; they are listed as risks. Three findings are major: the 10 s caller wait that is still hard-wired, the planned removal of the resolved `NodeCredentials` form (which the code still needs), and raw store output reaching the log before the value is known to the scrubber.

FINDINGS:
- [major] R-8 / plan stages 3–4, `AdapterGatewayFactory.SECRETS_WAIT` (AdapterGatewayFactory.java:113, 297-299), Wiring.java:317 and 319, `NodeSecrets.Cell.current` (NodeSecrets.java:334-341) – Every caller still waits for the secrets with `NodeSecrets.STORE_TIMEOUT` (10 s), and `Cell.current` waits `min(bound, timeout)`. With the 60 s credential store timeout, every tool call on a node gives up after 10 s while a Keychain dialog or an unlock prompt is open. It returns `TIMEOUT` "not yet available (still fetching)" with the Parameter Store text. This affects `gateway()`, `monitoring()`, `ports()` (all non-fan-out tools: process control, import, tag, deploy) and the e2e client. R-8 changes only `SecretTiming` and `get_health`. – Give `NodeSecrets` a `timeout()` per source (10 s or 60 s). Use it in `awaitCredentials()` and in the e2e function of `Wiring`, so that `SECRETS_WAIT` and the `STORE_TIMEOUT` uses are not hard-wired. Add a test: a single-node call whose fake store answers after 30 s succeeds.
- [major] plan stage 3 ("removal of … non-deferred `NodeCredentials`"), data-model "NodeCredentials (only the deferred form remains)" – This is backwards. `NodeSecrets.credentials()` builds the resolved `NodeCredentials` from fetched values (NodeSecrets.java:265-276). Every consumer works on the resolved form: `PortSetRegistry.NodeResources`, `CliExportRunner`, `CliImportRunner`, `CliTagRunner`, `V81ProcessControlAdapter`, `InubitHttpClient.create`, `CredentialGuard.bind`, `AdapterGatewayFactory.Slot.Client`. The form that becomes obsolete is the deferred placeholder (`deferred` flag, `NodeCredentials.deferred(...)`), because every node now has a lazy `NodeSecrets` and nothing needs a startup placeholder. – Keep the resolved record (values only ever built inside `NodeSecrets`). Drop the deferred flag and factory, and correct the data model and stage 3.
- [major] R-3 ("unknown stderr → `ACCESS_DENIED` with the scrubbed text in the log only"), R-5, data-model `Lookup.Found(String value)` – Constitution II. The stderr of `security … -g` carries the `password:` line. If the exit code or the format is unexpected (or the value breaks a `CredentialRules` rule and is refused), the value was never registered with the scrubber, so "scrubbed" log text still contains it. The same applies to `secret-tool` stdout on an unexpected exit. In addition, `Lookup.Found` is a record with a `String` component, so its generated `toString` prints the value. The `Fetched.Value` of 010 holds an `infra.Secret`. – Never log stdout of either tool. Before logging, drop every stderr line that starts with `password:`, and keep only the error lines. Make `Found` hold an `infra.Secret`. Add `KeychainStoreTest` and `SecretServiceStoreTest` cases with a password line plus a non-zero or unknown exit, and assert that the value is absent from the log.
- [minor] plan "Scale/Scope" and Source Code list, R-9, R-15 – Callers of removed or changed types that the plan does not name: `CredentialResolver.E2eCredentials` is used by `NodeSecrets` (import at NodeSecrets.java:3) and `Wiring`, and needs a new home. R-9 removes the no-re-read path, but `new CredentialGuard(labels, clock)` is used by the `InubitHttpClient` constructors (InubitHttpClient.java:124, 139, 176), which `V81MaintenanceProbe` reaches without credentials, and by about 20 tests. Also unnamed: `EffectiveNodeConfig.credentialVariables()`, `SslContexts` (`CredentialVariables.TRUSTSTORE_PASSWORD`), `TestWiring` (all `of(...)` take a `CredentialResolution`), and the `ConfigValidator` texts that still name environment variables (credential key in the file at :119-123, "come from environment variables" at :684/:698, `envPrefix` hints at :209/:258). R-15 lists `CredentialResolverTest` as switching to the fake store, but the class is removed. – Name them in the change list. Keep a guard constructor for unauthenticated clients (or pass a no-op `Rereadable`). Move `E2eCredentials` into `config`. Replace `CredentialResolverTest` with `LeftoverVariablesTest` and the `ConfigValidatorTest` collision cases.
- [minor] R-7, R-11, data-model `NodeSecrets.credentialStore(SecretPlan, CredentialStore, SecretScrubber, Clock)` – The factory receives nothing about `tls.trustStore`, the CLI configuration, `e2e.soap.baseUrl` or `e2eTests`, but R-7 and R-11 decide on them. `Cell` is built around one `ParameterStore.get` call over all names, while R-7 needs per-entry reads with node-to-group fallback. Its texts are tied to AWS: `unavailable()`, `pending()`, the interrupted message, `callError` using `location`, and the log keys `region`/`parameters`. Its e2e cell is `null` when there are no names, but a credential store node always derives e2e names and needs "none found → no basic authentication" as a result. – Pass the node's `EffectiveNodeConfig` (or the needed flags). Name the split into a per-source reader and per-source texts that leave the Parameter Store texts unchanged. Let the e2e cell yield `Optional<E2eCredentials>`.
- [minor] R-14 ("`LiveTarget` builds the node's `NodeSecrets` through … `SecretsFactory`") – `LiveTarget` builds no `NodeSecrets`. It resolves a `CredentialResolution` and hands it to `TestWiring` → `Wiring` (LiveTarget.java:119, 210-211; TestWiring.java:29-47). It also runs its own `ConfigValidator`, and `LiveTargetTest:164` reads `credentials().credentials(...)`. What is missing is a `CredentialStore` seam on `Wiring`/`TestWiring` next to `Supplier<ParameterStore>`: the fake store for every wiring test, `CredentialStores.forOs` in production and in `LiveTarget`. – Rewrite R-14 around that seam; `SecretsFactory` may then be unnecessary.
- [minor] R-8/R-9 – With the allowance only while not held, a rejected login on a node that holds credentials, inside a fan-out, starts a re-read of up to 60 s. `Cell.reread` joins without interruption, and the guard makes new attempts wait. No allowance covers this, so the branch ends in `TIMEOUT` and later calls on the node wait for the dialog. – State this behaviour (the branch reports `TIMEOUT`, the re-read finishes, the next call uses its result) and add it to `CredentialGuardTest`/`InventoryServiceTest`.
- [minor] Wiring `policy(...)` (Wiring.java:410-428, 294), Constitution VII – The audit account falls back to "(Parameter Store <name>)" for AWS nodes only. A credential store node (now every default node) has no account until its first read, so audit records written before that have no account, and `ImportService.Account` says "unknown". This is a regression for today's environment nodes, whose username was known at startup. – Add a fallback such as "(credential store <USERNAME account>)", with a test on the audit record.
- [minor] R-5 subprocess environment and path – `secret-tool` gets "the server's environment". That includes the leftover `INUBIT_*` credential variables that FR-003 warns about, which goes against the allowlist rule of `CliRunner` ("No credential variable ever reaches StartCLI"). The tool is also resolved through `PATH`. Clients started from a desktop session often have no `DBUS_SESSION_BUS_ADDRESS`, and libsecret then needs `XDG_RUNTIME_DIR` for the default bus. – Pass an allowlist: `DBUS_SESSION_BUS_ADDRESS`, `XDG_RUNTIME_DIR`, `DISPLAY`, `WAYLAND_DISPLAY`, `HOME`, `USER`, `LANG`, `PATH`. Prefer fixed candidates (`/usr/bin/secret-tool`) before a `PATH` lookup. State that `adapter/os` starts processes only through `ProcessLauncher`; `PackageBoundaryTest.onlyTheCliAdapterStartsOrInspectsProcesses` forbids `ProcessHandle` there too, for example for a "launchd session" check.
- [minor] R-5 platform facts (risk) – "Cannot create an item in a locked collection" is an error of `secret-tool store`, not of `lookup`. A dismissed unlock prompt in `lookup` most likely ends with exit 1, no output and no stderr, which looks the same as not found. Then "access denied" cannot be told apart on Linux, which affects US1-4, FR-011 and the manual step of FR-017. – Mark it as a risk to verify in the Linux live check. If it is confirmed, word the not-found message on Linux as "not found (or the unlock prompt was dismissed)" and document it.
- [minor] R-3 outcome mapping (risk) – The mapping relies on message texts. The exit code of `security` is the low byte of the OSStatus (44 `errSecItemNotFound`; by the same rule 128 `errSecUserCanceled`, 51 `errSecAuthFailed`, 36 `errSecInteractionNotAllowed`, 50 `errSecNoSuchKeychain`). The constitution asks for exit-code evaluation. The `SSH_CONNECTION`/launchd heuristic is unverified. – Map exit codes first and texts second. Record these codes and texts in the macOS live check before the release.
- [minor] R-4 / Technical Context ("JNA 5.x") – (a) The constitution requires pinned dependencies; 5.17.0 is already in the local repository. (b) A failed native load (blocked extraction of `jnidispatch.dll` to the temp directory, `UnsatisfiedLinkError`/`NoClassDefFoundError`) is an `Error`. The `NodeSecrets` worker catches only `RuntimeException` (NodeSecrets.java:381-385), so the attempt ends only through the 60 s `orTimeout`, as `UNREACHABLE` "timeout" instead of "store not available". – Pin the version. Map `LinkageError` in `WindowsCredentialStore` to `STORE_NOT_AVAILABLE` and test it through the `CredApi` seam.
- [minor] quickstart table, SC-006, FR-013 – No row tests SC-006 or the FR-013 `secret.fetch` record (`source=credentialStore`, `store`, `entries`, `changed`). Reads are per entry and serialised: username and password, plus the group fallback, make 2–4 sequential store calls. If the double answers each read in 100 ms, the first call is already 200–400 ms slower, so SC-006 fails as written. – Say what the 100 ms applies to (the whole node read, or a double tuned so the per-entry sum fits), and add rows for SC-006 and FR-013.
- [minor] R-13 `EntryCheck` – Group entries shared by many nodes are read once per node, so with "Allow" (not "Always Allow") `--check-config` opens a dialog per node per shared entry. The "ignored" trust store warning reads a secret only to warn about it. – Read each distinct account once per run. For existence-only checks, consider `security find-generic-password` without `-g`, which reads attributes only and presumably opens no dialog (to verify).
- [minor] R-16 – Three things are missing: what an access permission grants on each system (FR-015, Edge Cases "Access control of the store"), how to find duplicate entries (Edge Cases "Several entries"), and release notes naming the systems where the live check was executed (SC-007). – Add them to the docs list.
