  - `CredReadW` returns `boolean`, which JNA maps to the 4-byte Win32 `BOOL`. `Native.getLastError()` is read only when the result is `false`, on the same thread that made the call. That is the pattern `jna-platform` uses.
  - On success the pointer always goes to `CredFree` in `finally`.
  - The interface Javadoc explains why `LastErrorException` is not declared.

  - With the fair lock the order is deterministic: timed `tryLock` respects fairness through `hasQueuedPredecessors`.
  - With `new ReentrantLock()` the releasing thread almost always barges ahead and the test fails. This is not guaranteed in every run, but it is reliable in practice and is a good guard.
