Stage 1: what matches the plan

- SC-002 / FR-002, checked by search (`grep -rn "getenv\|environment" src/main`). No production path reads a credential value from the environment any more. What is left:
  - `System.getenv()` in `ConfigLoader.forSystem` (`INUBIT_MCP_CONFIG`, `INUBIT_MCP_PROFILE`, `APPDATA`).
  - `ConfigValidator` (`JAVA_HOME`, plus `LeftoverVariables`, which reads only "set and not empty").
  - `Launcher`/`Wiring`: the allowlist parent of `CliRunner` and `GitCli`, and `CredentialStores.forOs`. Each adapter passes on only its allowlist: Keychain gets `HOME`, `USER`, `LANG`; Secret Service gets the D-Bus, display and locale variables plus `HOME`, `USER`, `PATH`. No `INUBIT_*` variable is passed.
  
  `CredentialResolver`, `CredentialResolution`, `NodeSecrets.environment`, `rereadable()`, `NodeCredentials.deferred` and the validator's environment checks (`checkCredentials`, `checkE2ePassword`, `e2eCredentialVariables`) are all gone.
- T013 wiring:
  - `Wiring` takes a `CredentialStore`. `secrets(...)` builds `NodeSecrets.credentialStore(...)` for every node that does not use AWS.
  - Every `Slot` gets `new CredentialGuard(labels, clock, secrets)` (R-9). The constructor without `Rereadable` is still there for unauthenticated clients.
  - `awaitCredentials()` uses `secrets.timeout()`, and so does the e2e function in `Wiring`, for both `current(...)` and `e2e(...)`. `SECRETS_WAIT` is removed. So every non-fan-out wait uses the node's own timeout, the e2e path included.
- R-17 audit fallback: `Wiring.policy` is evaluated on every lookup. It returns the read username once one is held. Before that it returns `(credential store <node USERNAME> or <group USERNAME>)` and reads nothing. `WiringAuditTest` checks the sequence fallback → username → username on the audit record. The wording follows R-17. tasks.md T013 says "(credential store <account>)", which is the shorter form of the same thing.
- `Launcher.Context.system` passes `() -> CredentialStores.forOs(...)`, a supplier. It is called only in `serve()`, so `--check-config` and failed validations never build the store. Building it reads no entry. `SecretServiceStore` checks once, in its constructor, whether `secret-tool` is executable, which is a file-system check and reads no credential.
- T014 validator:
  - FR-003 (leftover variables): `LeftoverVariables.warning(environment, config)` is wired in `validate(...)`, so it runs both at startup and in `--check-config`. It names only the variables and covers `credentialNameSet()` (every kind of every node, AWS nodes included). `MainTest` pins the full text, and the "(typo?)" warning is gone.
  - FR-005 (entry-name collisions): `checkEntryNameCollisions` puts the node names and the group names of all credential store nodes into one map from name to set of owners, so it catches node–node, node–group and the trust store suffix case (node `truststore` against the group's `TRUSTSTORE_PASSWORD`). AWS nodes are left out (R-13). A missing username or password is no longer a startup error (FR-006): `MainTest` now expects exit 0.
- FR-006: the server starts without touching any store. `MainTest` builds the store through the context supplier, and `NodeSecretsCredentialStoreTest.nothingIsReadUntilTheFirstUse` covers that nothing is read before the first use.
