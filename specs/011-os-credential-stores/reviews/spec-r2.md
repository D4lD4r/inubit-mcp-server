FINDINGS:
- [major] FR-008 ("counts a node's read in that node's deadline as in feature 010 (010 research R-8)") – In 010, `SecretTiming.allowance` adds the fetch timeout plus 1 s of grace to the fan-out deadline of every Parameter Store node, "always, whether or not its secrets are held". Environment nodes get zero. Once the credential store is the default source and its timeout is 60 s, every fan-out branch of a default profile gets +61 s on every call, also when the credentials are held long ago. So the worst-case time of a fan-out before a partial result grows by about a minute for every installation. This changes every fan-out tool, and neither FR-008 nor SC-006 says so. – Decide and state the bound. For example: "a credential store node gets the read allowance only while its credentials are not held (`credentialsHeld`, which never reads); with held credentials, fan-out deadlines are as today." Or accept the +61 s explicitly and name the resulting worst case.
- [minor] FR-005 ("a top-level `source: { type: credentialStore, prefix }` stays accepted with the same meaning") vs FR-001 ("an override replaces the whole source including its settings") – Today the top-level `source.prefix` applies only to nodes that inherit the top-level source. The default prefix of an override without its own `prefix` is `credentials.envPrefix` or `INUBIT_<PROFILE>` (`ProfileConfig.credentialPrefix`, `SecretPlan.resolve`). FR-005 lists the top-level source prefix as one of the "profile-wide" prefixes, which reads as if group/node overrides inherit it. That changes which entry such a node reads, and which prefix FR-003 uses for Parameter Store nodes. – Say which applies. Either it is profile-wide now (and the change goes in the migration notes), or it applies only to nodes that inherit the top-level source, as today.
- [minor] Assumptions "Store per system" (Linux: "all unlocked collections … as `secret-tool lookup` searches them") vs US2 AS3 / Edge case "The store asks the person" (a locked store that can prompt waits for the unlock prompt) – If only unlocked collections are searched, a locked keyring never prompts and its entries are simply "not found". (`secret-tool lookup` itself does unlock locked items.) – Change it to "all collections of the user's Secret Service; a locked collection is unlocked through the session's prompt (US2-3)".
- [minor] FR-017 ("verifies identity mapping, value encoding and the not-found and access-denied outcomes") – A real store cannot produce "access denied" in an unattended check. macOS needs a person to click "Deny". The Windows Credential Manager has no per-entry access control for the current user's own credentials, so the outcome does not exist there. As written, FR-017 cannot be met on Windows and needs a person on macOS. – Limit the access-denied check to the systems where it exists, and allow it to be a documented manual step. Or require it only for the test doubles.
