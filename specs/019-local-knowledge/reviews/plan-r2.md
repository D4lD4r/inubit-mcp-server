FINDINGS:
- [major] research.md:227-242 – D-6 masks XML element content only through the end of the current line when the closing tag is later, so multiline `<dbPassword>`, `<Property encrypted="true">`, `type="Password"` and `name="…Password"` values can leak, contrary to FR-010, SC-002 and Principle II – scan XML element values across lines through the matching closing tag, failing closed through EOF for malformed input, and add multiline tests for every supported XML form.
- [major] research.md:126-136, spec.md:500-501 – the round-1 D-4 fix incorrectly claims upper-then-lower is a conservative approximation with no missed case-fold collisions; `ß` maps to `ss` while `ẞ` maps to `ß`, although both full-case-fold to `ss`, so both names can be created in violation of FR-004b – use actual Unicode case folding, justify any required dependency, and test at least `ß`, `ẞ` and `SS` as one collision class.
- [major] research.md:452-456,513-518, OsPrivateFileSystem.java:92-113,221-230 – the round-1 D-12 link fix remains check-then-use: `createDirectories` follows links and silently accepts an object inserted after the check, allowing an internal segment to be swapped for a link before creation or publication. Directly opening `.lock` also bypasses `openLockFile`, dropping Windows `NOSHARE_DELETE` protection and permitting lock replacement and concurrent writers – provide anchored, no-follow relative operations through `PrivateFileSystem` (for example `SecureDirectoryStream`, failing closed where unavailable), preserve `NOSHARE_DELETE`, and test concurrent link swaps plus Windows lock deletion/recreation.
- [major] research.md:457-465, contracts/mcp-tools-delta.md:210-238 – after publishing, pruning may fail and leave 11 versions, violating FR-014 and the output schema's `historyVersions.maximum: 10`; other post-publication I/O failures are still classified as `INTERNAL` with "note and history left as they were," which can no longer be guaranteed – define an explicit commit point, stage pruning reversibly before publication, and treat every failure after commit as a successful write with bounded warnings rather than an unchanged-state error.
- [major] contracts/mcp-tools-delta.md:123-139, research.md:148-190 – listing hits permit at most 20 topics, but the 20-topic rule applies only to record-tool input; a valid hand-written metadata block may contain more and would produce output that fails its declared schema – either impose and document a read-side topic cap with an explicit truncation indicator/warning, or remove `maxItems: 20` and rely on the existing 8 KiB metadata-block bound.
- [minor] research.md:253-254,406-418, contracts/mcp-tools-delta.md:180-205 – D-6 claims the secret finder sees at most 4 MiB, but record input has no schema bound and D-10 runs credential readiness and secret detection before the 256 KiB result-size check; the transport currently accepts lines up to 16 MiB – reject raw content that cannot possibly fit the note bound as the first audited service validation, before credential reads and secret scanning, and state the actual finder bound consistently.
- [minor] quickstart.md:35 – the test matrix says exceeding depth 16 causes `PRECONDITION_FAILED`, while D-9 says the listing stops with a warning and D-10's size walk is deliberately not depth-limited – change the test expectation to a listing warning for depth 16 and reserve `PRECONDITION_FAILED` for the one-million-entry size-walk bound.

VERDICT: CHANGES_REQUESTED

RESOLUTION (applied in "Feature 019: plan review round 2"):
- XML values: masked across lines to the matching closing tag, to the end of the text without one (D-6); tests listed.
- Fold: upper/lower repeated to a fixpoint (closes `ẞ`); verified against a `CaseFolding.txt` (C+F) test resource instead of adding ICU4J (D-4, spec plan decisions).
- Links: `.lock` via a new `openLockFileNoFollow` that keeps `NOSHARE_DELETE`; segments created one at a time with `createDirectory`. A concurrent same-user swap is declared outside the threat model (the user could write the notes directly); `SecureDirectoryStream` is not portable (Linux only) — recorded as a plan decision instead of adopted (D-12).
- Commit point: publication; failures after it are a success with warnings, `historyVersions` reports the real count, no `maximum` in the schema (D-10, contract, spec plan decisions). Reversible staging of pruning not adopted: it adds files that can be left behind, while a late prune keeps the operator's text and is repaired by the next write.
- Read topics: no `maxItems` on the read side; the 8 KiB block bound applies.
- `content` > 256 KiB refused in step 1, before credentials and scanning; finder bound stated.
- Quickstart: depth limit → listing warning; size walk fail-closed only at 1,000,000 entries.
