FINDINGS:
- [major] research.md:360-399, contracts/mcp-tools-delta.md:58-59,123-132, spec.md:270-285 – Search hits expose only a masked, single-line, 120-character-cut `name`, but reading requires the exact name "as listed." Consequently a valid hand-written note whose path contains a control character, a masked secret, more than 120 characters, or an NFC-normalized collision cannot be uniquely addressed after listing, contradicting FR-004's requirement that hand-written notes remain readable – separate the safe display name from an opaque lookup handle, return that handle in hits, accept it for reading (and writable operations where applicable), and define deterministic handling of duplicate normalized names.
- [major] research.md:154-193 – The front-matter writer is not closed over its accepted inputs: it always emits double-quoted strings while `\"` and `\\` escapes are forbidden, although valid titles, topics and MCP client names may contain quotes or backslashes. Moreover, preserving a valid near-limit hand-written block while adding the five server keys can move its closing delimiter beyond the parser's 64-line/8-KiB limit. A successful write can therefore create metadata that the next call classifies as malformed and refuses to update – define reversible escaping for server-written strings and validate the complete generated block against the parser limits before publication, refusing with `PRECONDITION_FAILED` if preserved unknown metadata prevents a valid block; add quote, backslash, 64-line and 8-KiB boundary tests.
- [minor] research.md:496-499 – The claim that timestamp names with `-2`, `-3`, … have chronological lexical order fails at `-10` (`-10` sorts before `-2`), so repeated writes sharing one clock instant can prune the wrong history version – use a fixed-width sequence suffix or parse and compare the numeric suffix, with a test covering more than ten same-instant writes.
