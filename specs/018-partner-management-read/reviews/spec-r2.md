- [major] FR-020 / FR-018 / FR-015 / Operational scenario 4 – The audit rule says "one audit record per contacted server". It does not cover a call answered fully or partly from the cache (FR-018), where no server is contacted. One reading writes no audit record and returns partner connection data. The other writes a record anyway. Operational scenario 4 only makes sense if every call that returns data writes a record. The gap gets bigger because story 4 fills the same cache without an audit (FR-015). – Proposed wording for FR-020: "Every call MUST write one audit record per targeted or compared server, whether that server's data came from INUBIT or from the cache (field `fromCache`), all records of one call sharing one call id; …". Add a scenario in which a cache hit writes its record.
