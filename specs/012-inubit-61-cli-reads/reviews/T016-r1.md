FINDINGS:
- [minor] src/main/java/de/dadecker/inubit/mcp/adapter/cli/CliRunner.java:312-336 (writeStdin) – All stdin is written at once, without waiting for the `Password:` prompt. If StartCLI 6.1 asks for the password again after a failed login instead of exiting, it would read `uname`, `ps …` etc. as more password attempts within the same process. The guard only stops further processes, not this. That could add failed logins against the account (lockout risk). Research D-5 chose this design and marks it REC, and the javadoc already flags it, so it is not a defect now. – Expected: when the recordings (Phase 8) are evaluated, check specifically how a failed interactive login behaves (exit vs. new prompt). If it prompts again, write commands only after the login succeeds.
- [minor] src/main/java/de/dadecker/inubit/mcp/adapter/cli/CliRunner.java:145-147 – `runSession` accepts a caller list that already contains `CliSessionCommand.EXIT` (it is public). An `exit` in the middle silently ends the session early, and the later commands produce no output, which would be hard to diagnose in the parser (V61SessionParser). – Expected: optional. Reject `EXIT` in `commands` with an IllegalArgumentException, or keep `EXIT` non-public and append it internally only.
