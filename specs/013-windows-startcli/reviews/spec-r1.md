- [major] FR-009 / Context / Edge Cases (Paths): the spec never mentions the existing path rule for values inside `--execCommand`. `CliPaths.PATH_VALUE = ^/[A-Za-z0-9_.\-/ ]{1,1023}$` (src/main/java/de/dadecker/inubit/mcp/config/CliPaths.java:13) applies to every export, import and history file below `java.io.tmpdir`. No Windows path can match it (drive letter, `:`, `\`; an 8.3 short temp path also contains `~`). Without a stated Windows rule every export, import, backup and deploy is refused. (a) FR-009 requires non-ASCII paths to work, but the macOS rule refuses them and FR-017 forbids changing macOS behaviour. (b) ConfigValidator skips the `java.io.tmpdir` usability check on Windows (ConfigValidator.java:145) and FR-010 does not require it. UNC paths and paths over 260 characters are edge cases without an outcome. – Add an FR for the Windows path rule inside the StartCLI command, the outcome for UNC and long paths, and the `java.io.tmpdir` check on Windows; decide whether "non-ASCII" in FR-009 covers paths inside the StartCLI command or only separately passed arguments.
- [major] Context "Unknown on Windows" / Key Entity "Windows StartCLI substitute" / SC-002: how `startcli.bat` forwards its arguments (`%*`, `%1..%9`, `set ARGS=` with delayed expansion), and whether single-quoted `--execCommand` values (`'value with spaces'`, `''`) reach StartCLI unchanged, is missing. If the substitute forwards arguments differently from the real batch, SC-002 proves nothing. – Add it to the unknowns, have the live check and a read-only recording of the shipped `startcli.bat` verify it, and require the substitute to forward arguments like the real batch files.
- [major] FR-006: "determined from recordings" is not enough; the console code page depends on the host locale (850, 1252, 65001). FR-004 freezes "the fixed Java runtime settings as today", which blocks a Windows-specific output-encoding setting. – Require identical parsed results regardless of display language and code page (at least 850, 1252, 65001); let FR-004 allow fixed Windows-only runtime settings and name it as an allowed difference under FR-001.
- [major] FR-003 / Edge Cases: the encoding of standard input is not addressed (password, 6.1 session commands; today UTF-8 plus `\n`, CliRunner.java:279). A non-ASCII password read in the console code page would fail as AUTH_FAILED and trigger the guard's pause or a lockout. – Add an edge case and an FR (accepted as on macOS, or refused before start naming the cause, never the value); state the expected line ending on stdin.
- [major] FR-002 / US2 AS1 vs FR-001: "either passed or refused" leaves open which values become Windows-only refusals; FR-001 allows only named differences. – Name the values that MAY be refused on Windows only, or require that every value accepted on macOS is passed literally; make US2 AS1 deterministic.
